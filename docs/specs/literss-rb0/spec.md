# 重做为 LiteRSS spec

> 本目录其余文档是各规划节点的一手依据（原目录 `docs/specs/mrrss-280/`，mrrss-280 各节点 resolution 里的路径指旧目录名）。
> `roadmap.md`「五」的 R1–R20 与 `docs-plan.md` 已并入下面各条 D；依据文档与本 spec 冲突时，以本 spec 为准。

## 1. Goal and scope

- 把 MrRSS 重做为 **LiteRSS**：桌面上的 FreshRSS 未读阅读器，只服务一条动线——未读列表 → 扫中文标题 → 点开（中文读正文 / 英文看 AI 摘要）
  → 值得细读或剪藏的去浏览器 → 以上已读。旧版功能堆积、同步会把别处的已读改回未读、正文可执行脚本，在旧代码上修补不划算。
- Acceptance（用户在自建构建上可观察到的）：
  - 侧栏按「全部订阅 → 分类 → 订阅源」显示实时未读数；顶部「未读 / 全部」切换；英文标题在列表里只显示中文译文。
  - 点开文章即标已读；在「未读」视图里已读的文章变灰不消失；同步到的新文章只在列表顶部提示「N 篇新文章」，点击才载入。
  - 点开只显示 RSS 正文（已缓存全文的显示全文）；点「抓取全文」才抓，成功替换显示，失败时显示中文原因和「在浏览器打开」。点「摘要」按阅读区显示的正文生成中文摘要；正文太短时不摘要并说明原因。
  - 单篇标已读/未读、源/分类/全部订阅「全部标为已读」、「此篇及以上 / 以下标为已读」都在 FreshRSS 网页端生效；批量已读可在约 8 秒内撤销。
    在别的设备读掉的文章，下次同步后本地也显示已读；LiteRSS 从不把别处的已读改回未读。
  - 「全部」视图能回看抓取后 90 天内的文章；在 FreshRSS 取消订阅的源，下次同步后本地文章消失。
  - 首次启动自动导入旧 MrRSS 的文章、标题译文、摘要、凭据和设置，旧目录与旧库不被修改（导入报告只存在库里供排查，界面不显示，用户 2026-09-27 确认）；旧版在运行时提示退出且不导入。
  - 与旧版 MrRSS 并行安装互不干扰；托盘、关闭到托盘、开机自启、窗口位置记忆。
  - 有新版本时点一次「更新」即下载、校验、安装并重启到新版（Windows 安装版与 macOS）；便携版提示并跳到发布页；失败时显示中文原因和发布页。
    （literss-rb0.29 grill 修订，用户 2026-09-28 确认：原为「提示并跳到发布页」。）
  - 正文和摘要里的脚本不执行；应用不请求任何外部字体或脚本。
  - Windows 上完整可用；macOS 能构建并发布安装包。
- Non-goals：
  - 已由 ADR 排除的：本地添加订阅（0002）、server/docker 部署（0005）、无头浏览器抓全文（0007）。
  - 本次裁掉的功能：收藏、稍后读、隐藏、筛选器、快捷键、浮动目录、页内查找、复制按钮、悬停已读、ActivityBar、上一篇/下一篇、
    全文翻译、AI 标题翻译、多 AI profile、用量统计、提示词编辑、排版设置、界面多语言、应用内音视频播放器、滚动自动已读。
  - Linux 平台；给外部 agent 的操作接口（mrrss-assistant Skill、Swagger，以及未来可能的 CLI/MCP）。
  - 更新：便携版的应用内更新、代码签名与 Authenticode、增量更新、预发布渠道、安装后回滚、不经用户点击的自动安装、「已下载，以后再装」。
  - 热修旧版的已知 bug 与安全漏洞（忍到切换）；改 `Referrer-Policy`（ADR 0003 的防盗链需重测，不属本次）。
  - 同步星标：服务端星标原样保留，LiteRSS 不读也不写。

## 2. Decisions

### D1: 新骨架、逐块迁移，按 S0–S9 推进

- 不原地删改：S1 一次删掉判为「删除 / 重写」的全部代码，换上新壳、身份常量、开发隔离、浏览器通道、CSP 与前端空骨架；留用模块
  （FreshRSS HTTP 层、全文抓取、百度翻译与语言检测、代理、加密、desktopapi、设置生成器、摘要的模型调用）留在原位，到用它的那一步再裁剪。
  理由：同步、数据库、路由都要换主键与权威模型，原地改的中间态跑不起来（roadmap「一」）。
- 顺序：S0 准备（打 `legacy-final` 标签）→ S1 清场与壳骨架 → S2 数据层与设置 → S3 同步核心与假 FreshRSS → S4 旧库导入 → S5 API
  → S6 前端 → S7 壳集成 → S8 改名、文档与发布 → S9 用户切换。依赖：S1→S2→S3→S4；S5 依赖 S3；S6 依赖 S5；S7 依赖 S1；S8 依赖 S1–S7；
  S9 依赖 S8。各步内容与验证点见 `roadmap.md`「四」，按本 spec 的 D 修订后执行。
- 旧代码只通过 `legacy-final`（`git show` 或只读 worktree）对照，主干不留 `legacy/` 目录：否则两套代码同时构建，agent 也会把旧代码当现行实现读。
- S1 之后到 S6 之前主干没有可用界面，这是接受的代价；期间用户照常用已安装的 v1.3.28。

### D2: 身份常量集中在一处，正式值为 LiteRSS，开发构建整体覆盖

- 名字 LiteRSS；UniqueID `io.github.mistakey.literss`；数据目录 `%APPDATA%\LiteRSS`（macOS 用对应的用户应用数据目录）；开机自启注册表值名、
  更新检查仓库、desktopapi 端口都取自同一处。正式端口不得是 1234（旧版占用）也不得是开发实例的端口：新旧版并行安装时旧版可能正在运行。
- 开发构建把这些值整体换成开发值（独立 UniqueID、portable 数据目录、独立 WebView2 用户数据目录、1235 端口），见 D5。
- Go module 路径、包名、安装包产品名与安装目录、发布工作流在 S8 改名；对外不再出现 MrRSS，唯一例外是 D17 的来源说明。
- 探测旧版用的互斥量名 `wails-app-com.mrrss.app-sim` 由已安装的旧二进制决定，是常量，不随新身份变化。

### D3: 平台是 Windows 与 macOS，放弃 Linux

- Windows 为主平台，完整人工验收；macOS 继续构建与发布，用户按需抽验，不作每次发布的门槛（唯一例外是 D20 的一次更新验收）。Linux 不再构建发布：CI 平台矩阵、
  构建文档里的 Linux 条目（D-Bus 单实例、WebKitGTK 等）退役（mrrss-280.18）。
- 凭据加密：Windows 用 DPAPI（当前用户范围）；macOS 沿用现有方案。

### D4: 桌面壳留在 Wails v3，钉版；壳薄，前端是纯 `/api` 客户端

- S1 升到当时最新的 v3 beta（不低于 `v3.0.0-beta.26`）并钉住；此后只为具体修复或阻断问题升级，PR 写明原因。每次升级重跑：隔离实例能启动、
  单实例生效、`WebviewUserDataPath` 可用、CSP 头被采用、长轮询不被截断、托盘 API 可用。退回 Wails v2 是后备，只在 v3 出现阻断缺陷时考虑。
  否决 Tauri sidecar（多一条工具链与进程胶水）和「本地服务 + 浏览器」主壳（生命周期、单实例、回环安全要自建）（desktop-shell.md）。
- 壳只做：窗口、单实例、系统浏览器打开链接、窗口位置（退出时保存，最小化哨兵坐标不保存也不采用）、托盘（中文菜单：显示窗口、立即同步、退出）、
  关闭到托盘、开机自启、窗口获得焦点与从睡眠恢复时触发同步（mrrss-280.4 推翻了删除托盘/自启的建议）、启动更新安装后彻底退出（D20）。
- 前端不引用任何 Wails 运行时，只用相对 `/api` 路径；因此同一份前端能在 Wails 窗口和浏览器取证通道里运行。
- Windows 窗口无系统标题栏（用户 2026-09-27 壳验收时裁决：系统标题栏与界面不搭）：前端顶栏兼作标题栏，自带应用图标、
  拖动区与最小化 / 最大化（还原）/ 关闭按钮。拖动与边缘缩放经 WebView2 宿主消息（`chrome.webview.postMessage` 发 `wails:drag`、
  `wails:resize:<边>`，Wails 窗口原生处理），不引入 Wails 运行时包；三个按钮经 `/api` 让壳执行，关闭与点 × 相同（按 `close_to_tray`）。
  双击顶栏在 Windows 上调与最大化按钮相同的 `/api`（Wails 的 `wails:drag:doubleclick` 只在 macOS 生效；用户 2026-09-28 确认），macOS 发该消息跟随系统偏好。
  页面里没有 `chrome.webview`（浏览器取证通道）时不显示窗口按钮、顶栏只是普通顶栏。边缘缩放、拖到屏幕边的贴靠与系统阴影保留；Windows 11 悬停最大化按钮弹出的贴靠布局能用 Wails 的 non-client-region 消息接上就接，接不上不阻塞。
  macOS 用隐藏标题栏、保留系统红绿灯按钮，顶栏同样可拖动（不设人工门槛，见 D3）。

### D5: 开发实例隔离与浏览器取证通道是开发开关，不是部署形态

- agent 只启动开发构建：独立 UniqueID、portable 数据目录、独立 WebView2 用户数据目录、1235 端口，只连假 FreshRSS（D6 的测试缝）。
  它能在用户实例运行时启动，且不碰用户实例与真实 `%APPDATA%`（dev-isolation.md 实测）。已安装版本的 UniqueID 在 agent 会话里一律不得用于启动。
- 浏览器取证通道：开发开关下由 desktopapi 挂前端静态文件，入口统一写 `http://127.0.0.1:<端口>/`。不用 Wails `-tags server`：
  它没有 Origin 防护、监听地址可能暴露到局域网，且会重新引入 ADR 0005 删掉的构建形态。同一个二进制、只监听回环，与 ADR 0005 不冲突。
- 回环防护：`Origin` 为空，或严格等于监听器自身的源才放行；拒绝 `same-site` 与 `cross-site`；保留回环 Host 检查。
  理由：Chrome 对带 `crossorigin` 的同源资源 GET 也带 `Origin`，旧规则连 CSS/JS 都拦成 403。
- 需要热更新时，Vite 代理只把 `Origin: http://127.0.0.1:5173` 改写为目标监听器的源，其他 `Origin` 原样转发；取证默认用「构建后由开发实例托管」。

### D6: 同步以 FreshRSS 条目 ID 为身份，本地只推用户意图，取消差异推送

- 文章主键是 FreshRSS 条目 ID。服务端所有的列（订阅、标签、`server_read` 镜像）只由拉取写入，唯一例外是推送成功后镜像按推送的值写入、下次拉取照常纠正
  （否则删掉意图后显示会退回旧镜像，实现期修订，用户 2026-09-27 确认）；用户操作只写意图表
  `pending_read(item_id, value, seq, attempts, last_error)` 与 `pending_mark_all`；显示状态 = 意图优先，否则镜像。
  否决「拉取后与本地做差异推送」：它把别处的已读改回未读，是旧版的根本缺陷（sync-model.md）。同 URL 的多个条目各自保留，按 URL 分组展开意图。
- 推送器：操作后防抖约 1 秒，按值分组，每请求约 250 个 `i`，推送成功后比较 `seq` 再删意图（推送在途时写入的新意图不被误删）；
  失败退避重试，单条被拒时二分定位并计入 `attempts`，永久失败有上限。
- 同步周期串行互斥，步骤：探测旧版 → 推送意图 → `subscription/list` 与 `tag/list`（只覆盖服务端所有列；成功且返回订阅数大于 0 或本地原本既无订阅也无文章时，
  删除不在列表中的源的文章及其正文、全文、译文、摘要、意图）→ 未读 ID 集（`xt=read`，`n` 一次取足，超量才续页）→ 高水位扫描（从最新往旧，
  到「本地最大条目 ID − 10 分钟」或「现在 − 90 天」为止）→ 用 `stream/items/contents` 每批约 100 条补齐本地缺失条目（不论已读与否）
  → 更新 `server_read` 镜像 → 按 D9 清理。不拉星标集。
  旧库导入只搬文章不搬订阅，导入后第一次同步时本地必然无订阅，所以空列表防护也数文章（实现期修订，用户 2026-09-27 确认）。
- 调度在后端且固定：启动、每 `freshrss_auto_sync_interval` 分钟、从睡眠恢复、窗口获得焦点（距上次不足 1 分钟跳过）、托盘「立即同步」、
  点击侧栏底部同步状态。没有「启动时同步」开关。
- 测试缝：假 FreshRSS（Go `httptest` 的 greader 服务，外加供开发实例连接的可运行开发工具），复现已查明的服务端行为：长格式与十进制 ID、
  `n` 无上限、续页 `c` 为包含上界且丢首条、`it`/`xt` 过滤、`edit-tag` 对任何 `i` 都回 `OK`、`mark-all-as-read` 按 `ts` 截断、令牌过期回 401。

### D7: 批量已读按条目 ID 推送，后端按批次撤销

- 「此篇及以上 / 以下标为已读」：前端把视图有序 ID 快照里范围内的 ID 列表发给后端，后端只对显示为未读的条目写意图，推送器逐条推送。
  不换算成 `ts` 区间：列表按 `(published_at DESC, item_id DESC)` 排序，而 `ts` 按抓取顺序截断，换算必然多标或漏标。
- 「全部标为已读」（源 / 分类含子分类 / 全部订阅）写 `pending_mark_all`，推送为 `mark-all-as-read`；`ts` 取该范围最新条目的抓取时间
  （当前视图取快照中的，侧栏右键非当前视图时取本地的）。直接执行不确认。
- 所有批量已读返回撤销令牌；后端在内存保存「这次由未读变为已读的条目 ID」约 60 秒，重启即失效。撤销时对这些 ID 写回未读意图；
  尚未推送的 `pending_mark_all` 直接删除。前端 snackbar 在窗口左下角，约 8 秒，悬停不消失。单篇操作不走撤销。

### D8: 列表是视图内稳定的快照，计数是实时值

- 列表成员在快照内固定，已读只变灰；新条目只进顶部横幅，点击才载入。快照一次返回视图的全部有序 ID，不分页：「此篇及以下」与全部已读要覆盖整个视图，
  含界面还没加载的部分，而 keyset 分页的后续页按当时的显示状态重新筛选，会让已读条目消失、补进的旧条目混入（实现期修订，用户 2026-09-27 确认；
  取代 sync-model.md 与 roadmap.md R6 里的 keyset 退化）。
- 侧栏未读数是实时值（按显示状态计，同 URL 折叠后计一次），每次操作和同步后随 `rev` 刷新。两者口径不同是预期的，不另做提示。

### D9: 本地库是 90 天内 reading-list 的完整副本，新库带版本化迁移

- 「全部」视图只读本地库，不在翻页时向服务端按需拉取。保留期 90 天按抓取时间（条目 ID ÷ 10^6 秒）计，写死不做设置；
  清理条件是早于保留期、显示为已读、没有待推送意图，连带正文、全文、译文、摘要删除（mrrss-280.14）。不设 `read_at`。
- `published_at` 只用于显示与排序：缺失、为 0、解析失败或晚于抓取时间 1 天以上时用抓取时间；早于抓取时间的原样保留。
- 新库从 `PRAGMA user_version = 1` 起步，迁移按版本追加；RSS 正文与全文分表，列级权威由表结构表达。
- 测试缝：迁移框架从 1 升 2 的样例测试。

### D10: 设置收缩为固定清单，拒收未知键，单一模型配置

- 用户可见：`freshrss_server_url`、`freshrss_username`、`freshrss_api_password`、`freshrss_auto_sync_interval`、`baidu_app_id`、
  `baidu_secret_key`、`llm_endpoint`、`llm_model`、`llm_api_key`、`proxy_mode`、`proxy_type`、`proxy_host`、`proxy_port`、
  `proxy_username`、`proxy_password`、`update_check_enabled`、`close_to_tray`、`startup_on_boot`。内部：窗口 x、y、宽、高、是否最大化。
  上次成功同步时间存 `meta`，不是设置。
- 模型键用 `llm_*`，不用 `ai_*`：旧库 `settings` 里同名的 `ai_*` 遗留值从未生效。
- 设置层拒收未知键：写入返回 400，加载时忽略并记日志。
- 设置面板是一个模态框、一页滚动，分组依次为：FreshRSS（含测试连接）、摘要模型（含测试连接）、标题翻译、网络代理、应用、关于。

### D11: 标题翻译只用百度，大模型只做摘要，摘要按需生成

- 英文标题用百度翻译，列表只显示中文译文，原文在详情页；标题语言检测按书写系统（pitfall 11），译文等于原标题表示「已判定为中文」（pitfall 12）。
- 点开只显示 RSS 正文，不自动抓全文；已缓存全文的直接显示全文。阅读区的「抓取全文」按钮才抓：成功替换显示，失败保留 RSS 正文并显示中文原因 +「在浏览器打开」。
  RSS 正文不足 300 个可见字符时提示可以先抓全文。（2026-09-28 修订，literss-rb0.32：截断猜测会让站点拦截页替换完整的 RSS 正文，也让摘要总结拦截页。）
- 「摘要」按钮才生成摘要；输入只用阅读区当前显示的正文：有缓存全文用全文，否则用 RSS 正文，后端不自行抓取；太短不摘要并显示原因。
  抓到全文后，已有的（基于 RSS 正文的）摘要作废并按全文重新生成。
  提示词写死，输出固定中文。摘要 Markdown 渲染时不接受原始 HTML。

### D12: 旧库只读、一次性导入

- 首次启动在旧固定路径查找旧库（可用环境变量指定），按表结构识别，只读打开并 `VACUUM INTO` 快照后导入，`meta` 记 `legacy_import` 后不再查找；
  从不修改旧目录与旧库，旧版即回退路径。否决原地迁移（主键与表几乎全换，同时踩 pitfall 19、20）与只靠重新拉取（译文、摘要、凭据拉不回来）。
- 搬运：有条目 ID 的文章（无 ID 的丢弃）、RSS 正文、标题译文（含「已判定中文」值）、摘要；未同步队列按（条目, read）取最后一条转 `pending_read`，
  星标意图丢弃；设置按 D10 白名单导入，模型配置按旧解析链从 `ai_profiles` 取一条写入 `llm_*`；凭据旧格式解密后按 D3 重新加密，失败只丢该项并在
  报告里提示重填；窗口坐标丢弃最小化哨兵值。不导入 feeds（首次同步重建）、翻译缓存、上次同步时间。
- 导入先于第一个同步周期；探测到旧版在运行时推迟导入并提示退出旧版。导入的旧文章按 D9 在第一个周期末尾清理，这是接受的结果。
- 测试缝：按 `legacy-final` 旧建表语句在测试中生成的合成旧库；agent 不读用户真实库。细节见 data-migration.md。

### D13: API 只为自己的前端设计，改状态只收非 GET，路由表测试是唯一真相

- 路由清单：列表快照、按 ID 取卡片、正文、抓全文、标题翻译、摘要、单篇标已读/未读、按 ID 批量标已读、按流全部已读、撤销、未读计数、订阅树、
  设置读写、测试 FreshRSS 连接、测试模型连接、立即同步、同步状态长轮询、在浏览器打开、版本、检查更新、开始更新与更新状态（D20）。其余旧路由全部删除。
- 会改状态的接口只收 POST/PUT/DELETE，GET 一律 405。列表摘录由后端抽成纯文本。
- 删除 Swagger 与 mrrss-assistant Skill（mrrss-280.17），pitfall 18 退役；路由表的表驱动测试守住方法约定。

### D14: 同步状态走 HTTP 长轮询

- `GET /api/sync/state?since=<rev>` 挂起约 25 秒；载荷含运行中、新条目数、待推送数、上次成功时间、错误、`legacy_running`。
- 否决 Wails 事件（前端要依赖 Wails，取证通道测不到真实路径）与 SSE（Wails v3 Windows 的响应写入器不支持 flush）（sync-push-channel.md）。
- desktopapi 不设短于长轮询的 `WriteTimeout`；等待同时监听请求 context 与关闭信号，`Shutdown` 时唤醒。

### D15: 前端按布局变体 B 重写，去掉 i18n、Tailwind 与 Wails 绑定

- 保留 Vue 3 + TypeScript + Vite + Vitest + Pinia；删除 Tailwind（改用原型的 CSS 变量 + scoped CSS）、vue-i18n（文案直写中文）、
  `@phosphor-icons/vue`、`@wailsio/runtime`、Cypress。主题只跟随系统。不加载任何外部资源。复用清单见 frontend.md。
- 布局以 `layout-prototype/` 变体 B 为基础，按 mrrss-280.6 修改：三栏；侧栏顶部「未读 / 全部」分段切换，底部设置与可点击的同步状态；
  列表每条为标题（最多两行）+ 一行中文摘录 + 有配图才显示的右侧缩略图；详情无工具栏，「摘要 / 在浏览器打开 / 标为未读」在底部浮动条，
  无上一篇/下一篇与关闭按钮；文章右键有已读/未读、此篇及以上/以下标为已读、在浏览器打开；源/分类/全部订阅右键有全部标为已读。
- 图片查看器：点图打开，滚轮以指针为中心缩放，双击在适应窗口/原始大小间切换，放大后拖动平移，点背景 / 右上角 ✕ / Esc 关闭，多图左右箭头切换；无复制/下载。
- 正文排版写死：系统无衬线（Segoe UI + 微软雅黑 / 苹方），17px，行高 1.8，最大行宽 700px，标题 26px。

### D16: 不信任的 HTML 在前端用 DOMPurify 清洗，外加 CSP 响应头

- 正文与摘要只经同一个清洗函数进入 `v-html`；eslint 保留 `vue/no-v-html`，只在这两个组件豁免。白名单为 HTML + MathML，禁 style/form 类标签与
  style/id/name 属性；URL 只收绝对 `http(s):`、`mailto:`、`data:image`，删除指向自身源与回环主机的地址；后端原样存取。
- `iframe`、`embed`、`object`、`video`、`audio` 一律替换为「在浏览器打开嵌入内容」链接（只接受 `http(s):`）。
- CSP 由前端静态文件 handler 在 Wails 资源与 desktopapi 两条通道统一以响应头下发（`script-src`/`style-src 'self'`，`img-src 'self' http: https: data:`，
  `font-src 'self' data:`，`frame-src`/`object-src 'none'`）。S1 在隔离实例确认 WebView2 采用响应头；不采用时退到构建期注入 `<meta>`。
- 删除后端正则式的 `SanitizeHTML`/`CleanHTML`。公式与代码语言识别兼容 FreshRSS 的 `data-sanitized-class`，或给 readability 打开 `KeepClasses`，由实现选。
- 否决只靠 CSP 或只靠后端清洗：Chrome 实测任一层都能拦住已知向量，两层并用防单点失误；后端正则清洗已被多种写法绕过（html-sanitize.md）。

### D17: 以独立新项目 LiteRSS 发布，仍是 GPL-3.0

- 代码搬用了 MrRSS 的部分模块，许可证保持 GPL-3.0，LICENSE 原样保留，README 一行「派生自 MrRSS」；除此之外对外不出现 MrRSS。不再跟随上游。
- 重做期间在本仓库带历史开发；发布时以 orphan 提交作为新仓库起点，本地目录同时改名。新写的文档不引用旧提交号。
- 新仓库须公开：更新检查用未认证的 GitHub releases API。仓库怎么建、旧 fork 怎么处置，在 S8 发布前由用户确认（见 §3 人工门）。
- README 与首个发布说明写明：FreshRSS 默认 `keep_unreads = false`，积压 3 个月以上或每源超过 200 篇的未读会被服务端删除；
  新旧版不得同时连同一账号运行，切换前要从托盘彻底退出旧版。

### D18: 重做期间旧版照常用，新版防护旧版

- S0–S8 期间用户照常用已安装的 v1.3.28；开发与 agent 验证只连假 FreshRSS、只用隔离数据。
- 新版每个同步周期开始时只读探测旧版互斥量；探测到时同步状态带 `legacy_running`，侧栏底部显示「旧版 MrRSS 正在运行，会把已读改回未读，请退出」，
  不暂停同步（回退是旧版做的，暂停保护不了什么）。回退路径：退出新版、打开旧版即可。

### D19: 文档与代码在同一提交里变化

- 删代码的提交同时删描述它的文档段落，不加「已过时」标记；未落地的部分以本 spec 为唯一权威，ARCHITECTURE 只写已存在的东西。
- S1 起 AGENTS.md 重写，含「重做进行中」一节（spec 路径、`legacy-final` 对照方法），forge:finish 删除 spec 时一并删除；
  「开发实例与取证」一节取代 Common Issues 7，同一提交改 `.forge/config.md` 的 human acceptance 一行。
- ADR 0008–0018、`docs/out-of-scope/` 新记录与 `CONTEXT.md` 已在 spec 收尾写入，ADR 0001 已标为被 0017 取代；
  docs-plan.md 里「S8 写 ADR 0016 / 改 0001 状态」的安排作废，后续步骤只在实现偏离时更新或取代 ADR。
- 各步骤要删、改、新增的文档与 pitfall 按 docs-plan.md「三」「五」执行（mrrss-assistant 按 A 删除、平台按 D3 收窄）；forge:slice 把对应项写进 Issue 验收。

### D20: 应用内一键更新：Windows 按用户安装静默升级，macOS 原子替换 `.app`，SHA-256 校验

（literss-rb0.29 grill，用户 2026-09-28 确认；取代原「只提示并跳到发布页」，影响 literss-rb0.22 的安装包与发布工作流。）

- 范围：正式身份的 Windows 安装版与 macOS `.app` 做应用内安装；便携版（exe 旁有 `portable.txt`）与无法确定安装位置的情况仍提示并跳到发布页。
  旧版 MrRSS 的应用内更新（`legacy-final:internal/handlers/update/`）只作对照，不搬运。
- 资产与校验：发布工作流给全部产物生成一个 `SHA256SUMS` 随发布上传。按 `runtime.GOOS/GOARCH` 选 `LiteRSS-<ver>-windows-<arch>-installer.exe`
  或 `LiteRSS-<ver>-darwin-<arch>.dmg`；下载地址只接受 releases API 返回的、属于 `identity.UpdateRepo` 那次发布的资产。
  缺资产、缺校验和或校验不符：删掉下载的文件，进入失败态并给发布页。自用场景下它防的是下载损坏与中途篡改，信任根仍是 GitHub 账号，与手动下载相同。
- Windows 安装：安装包改为按用户安装（`RequestExecutionLevel user`），默认 `%LOCALAPPDATA%\Programs\LiteRSS`，保留目录页可自选，目录与卸载项记在 `HKCU`。
  应用内更新以 `/S /D=<当前 exe 所在目录>` 运行安装包，装回正在运行的位置；该目录当前用户不可写时以 `runas` 提权运行（一次 UAC）。
  安装包在静默安装后、以及交互安装完成页的「启动」，都经 `explorer.exe` 启动 LiteRSS，保证以普通权限运行（否则提权安装会让应用跑在管理员下）。
- macOS：挂载 DMG（`hdiutil attach`），把新 `.app` 复制到当前 `.app` 同目录的临时名，启动辅助脚本后 LiteRSS 退出；脚本等原 PID 退出后以改名原子替换
  （旧的挪开 → 新的放入 → 删旧的），任一步失败恢复旧的，然后卸载 DMG、`open` 新版。当前 `.app` 所在目录不可写时退回跳发布页。
  Go 自己下载的文件不带 `com.apple.quarantine`，临时签名的包因此不被 Gatekeeper 拦。替换计划由 Go 生成、可单测，脚本只执行它。
- 交互：后端一个更新状态机（空闲 → 下载中（进度）→ 校验 → 启动安装 → 彻底退出；失败态带中文原因与发布页），两个入口共用：
  托盘自动检查的原生对话框「更新 / 以后」，设置面板「检查更新」查到新版后的「更新到 X」与进度。点一次走完，不二次确认；
  启动安装后彻底退出，不走 `close_to_tray`。托盘触发的失败用原生对话框（原因 +「去发布页」），面板触发的在面板显示。
- 出站走共享 `httputil` 客户端（pitfall 8）；安装包下到系统临时目录下的 `LiteRSS-update`，下次启动清理。
- 开发构建（D5）绝不启动安装包：只有正式身份允许，开发构建走完下载与校验后停在「开发构建不安装」终态并记录本会执行的命令。
  开发构建可用环境变量把 releases API 基址指向假发布服务，供隔离实例做界面取证；正式构建忽略该变量。启动安装包的一步是注入函数，单测断言命令与参数。

## 3. Verification

- agent：
  - S1：防护矩阵单测（同源 POST 与带 `crossorigin` 的同源资源 GET 放行；异源、`same-site`、`cross-site`、非回环 Host、`localhost` 别名拒绝）；
    两条通道都带 CSP 头；开发构建与正式构建的身份常量不同、正式端口不是 1234。用户实例运行时启动隔离实例：`127.0.0.1:1235/api/version` 返回 200，
    用户实例仍在且 PID 不变，真实 `%APPDATA%` 无新目录；Chrome headless 打开 `http://127.0.0.1:1235/` 渲染三栏空壳，无 403、无 CSP 违规、无外部请求；
    WebView2 采用 CSP 头的实测结论。
  - S2：建库与 `user_version`、迁移 1→2、未知键拒收、加密字段往返；设置生成器产物与 schema 一致，前端类型能编译。
  - S3（全部对假 FreshRSS）：在服务端被别处标已读、本地无意图的条目，周期后本地显示已读且从不被推回未读；续页边界行为；拉取不覆盖待推送意图；推送在途写入的新意图不被误删；单条被拒时二分定位并计入 `attempts`；
    取消订阅的源的文章被删除、`subscription/list` 返回 0 个订阅时跳过；90 天清理规则；高水位扫描补上别处读掉的新条目；
    长轮询在状态变化时立即返回、25 秒超时返回、`Shutdown` 时被唤醒；批量已读撤销（未推送的删行、已推送的写回未读）。
  - S4（合成旧库）：无 ID 文章丢弃、同 URL 多条目各自保留、「已判定中文」译文原样搬运、未同步队列转意图且丢星标、白名单外设置丢弃、
    凭据解密失败只丢该项、导入先于第一个同步周期、旧版运行时推迟且不写 `legacy_import`。
  - S5：路由表测试断言每个改状态的路由对 GET 返回 405；handler 单测覆盖快照、按 ID 取卡片、按 ID 标已读、撤销；
    标题翻译对假百度端点：英文标题存译文、中文标题存「已判定」值；抓全文失败返回中文原因；摘要在全文失败时基于够长的 RSS 正文并注明原因、太短时拒绝并给原因
    （模型与网页都用 `httptest` 替身）。
  - S6：vitest 覆盖 store 的「快照在视图内稳定」「新条目只进横幅，点击才载入」、撤销、清洗器载荷矩阵（html-sanitize.md 第 1、2、4 节，
    外加应保留的 `mailto:` 与 `data-sanitized-class`）；每个子步骤在浏览器通道里对「隔离实例 + 假 FreshRSS」截图，对照 D15。
  - S7：窗口状态的哨兵过滤、开机自启注册表值名、更新检查仓库地址的单测；隔离实例能启动并响应 API。
    无边框顶栏：窗口按钮路由进路由表测试（GET→405）并各有 handler 单测；浏览器通道截图里顶栏不显示窗口按钮。
  - S8：新仓库 CI 通过（Windows 与 macOS）；发布产物与旧版的安装目录、数据目录、UniqueID、自启键、端口都不同；

    便携版与开发构建不安装、Windows 安装命令（`/S /D=<exe 目录>`，目录不可写时 `runas`）、macOS 替换计划（含失败恢复与目录不可写时退回）、
