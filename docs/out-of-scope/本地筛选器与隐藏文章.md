# 不做本地筛选器与隐藏文章

**决定（2026-09，用户裁定，项目 LiteRSS 重做）：删除条件筛选器（含筛选计数）与「隐藏 / 显示隐藏文章」，各源的本地「从时间线隐藏」偏好一并删除。**

## 为什么否决

动线从未读列表开始，按「全部订阅 → 分类 → 订阅源」的侧栏缩小范围已经够用，动线里没有按条件组合筛文章的一步。
不想读的文章，动线给的处理方式是标为已读——它还会同步到 FreshRSS，而「隐藏」只存在于本机，
在网页端和别的设备上仍是未读，等于在已读之外另造一种只在本地生效的状态。

维护代价：筛选器有独立的弹窗、条件编辑组件、三个 composable、两个后端接口和一套自拼的查询条件；
隐藏状态要在列表查询、未读计数和同步里处处特判。新同步模型只认服务端所有列和已读意图，没有给本地私有状态留位置。

## 因此

- 缩小范围靠侧栏的分类与订阅源；不想读就标为已读或「全部标为已读」，批量已读可撤销。
- 订阅的增删与分类都在 FreshRSS 管理。
