# 不做多 AI profile、用量统计与提示词编辑

**决定（2026-09，用户裁定，项目 LiteRSS 重做）：大模型只有一套配置（端点、模型、密钥，外加测试连接），只用于摘要；删除 profile 列表与选择器、自定义请求头、用量统计与上限、摘要长度和提示词编辑。**

## 为什么否决

动线里大模型只做一件事：用户点「摘要」时给英文文章生成中文摘要。标题翻译已固定走百度，没有第二个用途需要
按任务切换模型，profile 列表只剩一个条目。摘要只在点按钮时生成，不会因批量点开文章而失控，用量上限这道护栏没有保护对象。
提示词与长度写死、输出固定中文后，用户也没有需要调它的一步。

维护代价：profile 有独立的表、增删改与批量测试接口、两个 profile 选择设置、厂商图标识别；
「哪个配置生效」要走一条多级解析链，旧库里同名的 `ai_*` 设置值就因此从未生效过。用量统计要在每次调用后计数并提供重置接口。

## 因此

- 设置只有 `llm_endpoint`、`llm_model`、`llm_api_key`；旧库导入时按旧解析链取一条 profile 写入这三项。
- 摘要提示词写死在代码里；想换模型就改这三项。
