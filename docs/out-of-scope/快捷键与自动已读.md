# 不做快捷键、悬停已读与滚动自动已读

**决定（2026-09，用户裁定，项目 LiteRSS 重做）：删除键盘快捷键及其设置页、悬停标记已读、滚动自动标记已读；同时删除上一篇 / 下一篇导航。**

## 为什么否决

用户全程用鼠标阅读，快捷键没有使用者；Esc 关闭图片查看器这类局部按键由组件自己处理，不需要全局快捷键系统。
上一篇 / 下一篇同理：三栏布局里列表始终可见，看完一篇直接在列表点下一篇。

悬停已读和滚动已读都是「不点开就判已读」。动线里已读有明确的两个来源：点开文章即已读，扫完一段后用右键
「此篇及以上 / 以下标为已读」或「全部标为已读」清掉，并且批量已读可撤销。自动已读容易误触，误标的文章会被推送到 FreshRSS，
在别的设备上也消失；它还让列表成员在视图内变化，与「列表是视图内稳定的快照，已读只变灰」相冲突。

维护代价：快捷键有设置项、设置页、全局监听和与输入框的冲突处理；两种自动已读各有开关，并在列表组件里占用大量分支。

## 因此

已读只来自点开文章和显式的右键 / 批量操作；详情页的「标为未读」是单篇误读的纠正手段。
