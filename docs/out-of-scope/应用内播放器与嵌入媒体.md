# 不做应用内音视频播放器与嵌入媒体

**决定（2026-09，用户裁定，项目 LiteRSS 重做）：删除应用内音频、视频播放器；正文里的 `iframe`、`embed`、`object`、`video`、`audio` 一律替换为「在浏览器打开嵌入内容」链接。**

## 为什么否决

用户的真实旧库 10938 篇文章里，带音频或视频附件的是 0 篇；用户不订阅播客或视频源，播放器没有使用场景。
动线本来就规定「值得细读的去浏览器」，视频这类内容在浏览器里看体验更完整。

维护与安全代价：播放器组件挂在正文组件里，与翻译、目录等逻辑交织；保留嵌入就要维护 `iframe` 白名单、
放开 CSP 的 `frame-src` 与 `media-src`，而正文是不受信任的第三方 HTML，嵌入框架正是需要堵住的执行面。

## 因此

- 清洗器把上述标签换成只接受 `http(s):` 的外链，点击走系统浏览器；CSP 保持 `frame-src`/`object-src 'none'`，不设 `media-src`。
- 以后若开始订阅播客，先评估「在浏览器打开」是否够用，再考虑播放器。
