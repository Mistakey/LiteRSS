# 应用内一键更新，Windows 安装包改为按用户安装

> Source: literss-rb0 (D20)；Issue literss-rb0.29

最初的设计是有新版本时只提示并跳到发布页，由用户在浏览器里下载安装。用户 2026-09-28 改为应用内一键更新：点一次「更新」即下载、按随发布上传的 `SHA256SUMS` 校验、安装并重启到新版。Windows 安装版以静默参数运行安装包装回当前目录；macOS 挂载 DMG，由辅助脚本在应用退出后以改名原子替换 `.app`，失败时恢复旧的。为了让静默更新不弹 UAC，Windows 安装包从装进 `Program Files` 的管理员安装改为按用户安装（默认 `%LOCALAPPDATA%\Programs\LiteRSS`，目录仍可自选）；装在当前用户不可写的目录时才提权。便携版不做应用内更新，仍跳发布页；开发构建绝不启动安装包。

## 被否决的方案

**保持 `Program Files` 管理员安装。** 每次更新都要点一次 UAC，而且提权后的安装包直接启动应用，会让界面和 WebView2 跑在管理员权限下。改安装方式在第一个版本发布之前没有迁移成本。

**交互式安装向导代替静默安装。** 更新时弹完整向导让用户逐页点完，不再是「点一次」。

**便携版替换自身 exe。** 替换正在运行的程序要另起辅助进程或改名周转，出错可能把唯一的一份程序弄坏；便携版不是用户日常用的形态，不值得这条风险路径。

**Ed25519 签名或 Authenticode 代替 SHA-256 校验和。** 自用项目的威胁主要是下载损坏；私钥若放在 CI 里，签名与校验和同样以 GitHub 账号为信任根，只多了密钥管理。Authenticode 需要每年购买证书。

## 后果

- 不要把安装包改回 `RequestExecutionLevel admin`：应用内更新依赖按用户安装才能不弹 UAC。
- 安装包静默安装后与完成页的「启动」都要经 `explorer.exe` 启动应用，否则提权安装时应用会以管理员身份运行。
- 装在当前用户不可写目录的副本经 `runas` 更新时，若提权到的是另一个管理员账号，安装包写的 `HKCU` 卸载项与开始菜单、桌面快捷方式会落在那个账号下。自用场景接受这一点，没有为它改回 `HKLM`。
- 只有 exe 旁有安装包写下的 `Uninstall.exe` 才算安装版；手动复制出来的 exe 与便携版一样只给发布页，避免把安装包装进一个随手放的目录。
- macOS 的应用内更新依赖 Go 下载的文件不带隔离标记；若将来改由浏览器或系统服务下载，临时签名的包会被 Gatekeeper 拦下。
