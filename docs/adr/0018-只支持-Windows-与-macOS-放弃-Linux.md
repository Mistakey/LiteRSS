# 只支持 Windows 与 macOS，放弃 Linux

> Source: literss-rb0 (D3)；规划地图 mrrss-280

旧 MrRSS 继承上游的三平台构建与发布，但用户只有 Windows 和 macOS 设备。决定 LiteRSS 只支持这两个平台：Windows 是主平台，每次发布完整人工验收；macOS 继续构建并发布安装包，由用户按需抽验，只以 CI 构建通过兜底，不作为每次发布的门槛。Linux 不再构建发布：CI 平台矩阵去掉 Linux，构建文档里只为 Linux 存在的条目（D-Bus 单实例约束、WebKitGTK 等系统依赖）退役。理由：没有人能验收的平台，发布出去就等于发布未测过的东西。

## 被否决的方案

**三平台同等支持。** 没有 Linux 设备就做不到同等验收，「同等支持」只是名义上的。

**Linux 继续构建但不验收。** CI 会一直为它付构建与依赖维护成本，启动相关改动还要顾及 D-Bus 单实例这类只在 Linux 出现的约束；而产物仍是无人测过的东西，用户拿到坏包时无从修复验证。

## 后果

- 不要因为「只差一个构建目标」就把 Linux 加回 CI 矩阵；恢复支持的前提是有人能在 Linux 上验收。
- macOS 不是验收门槛，因此 macOS 上的问题可能在发布后才被发现，这是接受的代价。
