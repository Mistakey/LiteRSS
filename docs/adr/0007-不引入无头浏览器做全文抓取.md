# 不引入无头浏览器做全文抓取

> Source: mrrss-c58513 (§1 Non-goals)；spec 原文 `git show fe3c371b:docs/tracker/全文抓取增强/spec.md`

前端渲染的站点抓不到正文，自然的补救是在正文过短时用无头浏览器重跑页面——这曾是 Issue `mrrss-2c509d` 的主张。2026-08-29 用真实订阅数据实测后决定不做，并关闭该 Issue。

## 被否决的方案

**正文低于阈值时回退到无头浏览器渲染。** 三条理由，按份量排列：

1. **覆盖面极小。** 全库真正属于「SPA 渲染导致抓不到」的只有 `chadnauseam.com`（43 篇）与 `danielwirtz.com`（10 篇），合计 53 篇 = 全库 7137 篇的 **0.7%**。
2. **相当一部分「渲染失败」的页面无头浏览器也救不了。** 实测归类中，youtube 视频页、PDF、linkedin 活动页、SPA 落地页报的都是同一个 `Node == nil`，但它们不是渲染问题——**这些页面本来就没有文章正文**，渲染多少次都变不出来。
3. **成本已经变了。** `chromedp` 随 `internal/feed` 一并删除后（见 [ADR 0002](0002-定位为纯-FreshRSS-客户端.md)），go.mod 与全部 Go 代码中已无痕迹。重新引入是新增依赖 + 分发体积，不再是「复用已有依赖」。

参照：Miniflux（成熟的 Go RSS 阅读器）**完全不做无头浏览器**，只做规则表 + readability 回落。

## 后果

- **SPA 站点抓不到正文是已知且接受的状态，不要为它加无头浏览器。** 这类失败归入「此页无正文」分类并提供浏览器打开原文。
- reddit 因此也不做（`www.reddit.com` 是 SPA，`old.reddit.com` 403，`.json` 端点 403 Blocked），尽管它占 buzzing 系文章的 30%。
- 可逆，但代价不对称：一旦引入无头浏览器，依赖、分发体积与「浏览器版本跟进」的长期维护都会回来。
