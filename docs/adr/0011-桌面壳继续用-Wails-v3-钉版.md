# LiteRSS 桌面壳继续用 Wails v3，钉版且只为具体问题升级

> Source: literss-rb0 (D4)；规划地图 mrrss-280

Wails v3 仍是 beta：2026-08 发布 Beta 后每晚自动发一个新 beta，GA 前还有数十个发布闸门（多数是阻断项）未通过、没有日期；官方同时说明桌面 API 已稳定、已有团队用于生产。风险在于版本号天天变，不在 API 大改。决定：S1 升到当时最新的 v3 beta（不低于 `v3.0.0-beta.26`，它修了「WebView2 进程失败后留下空白窗口」）并钉住；此后只为一个具体的修复或阻断问题升级，PR 写明原因。壳保持薄：Wails 只出现在 `main.go`（外加可选的小壳包），只做窗口、单实例、系统浏览器打开链接、窗口位置、托盘、关闭到托盘、开机自启、焦点与唤醒触发同步；前端不引用任何 Wails 运行时（见 [ADR 0010](0010-同步状态走-HTTP-长轮询.md)）。

## 每次升级要重跑的检查

1. 用户实例运行时，隔离的开发实例仍能启动（[ADR 0012](0012-开发隔离与取证通道是开发开关不是部署形态.md)）。
2. 单实例仍然生效。
3. `WebviewUserDataPath` 仍然可用。
4. WebView2 仍采用 CSP 响应头。
5. 同步状态长轮询不被资源服务器的缓冲写入器截断或阻塞其他请求。
6. 托盘 API 可用。

探测旧版 MrRSS 用的互斥量名 `wails-app-com.mrrss.app-sim` 由已安装的旧二进制决定，与新版钉哪个 Wails 版本无关，升级时不要改。

## 被否决的方案

- **Tauri + Go sidecar。** Go 后端一行不省，只能作为 sidecar 独立进程：要按目标三元组命名、声明 `externalBin`、授予 spawn 权限，生命周期、端口协商、崩溃重启和单实例都要写 Rust 胶水。多一门语言和 MSVC + Rust 工具链；Go sidecar 约 25–30 MB 仍占大头，体积没有优势。
- **本地服务 + 系统浏览器作主壳。** 服务生命周期（标签页关了何时退出）、单实例、回环安全（任何本地网页都能访问 localhost，只靠 Origin 拦截不够，要加 token）都要自建，还失去独立窗口身份。它唯一的优点「能用浏览器取证」已由开发取证通道拿到。
- **一直跟最新 beta。** 每晚一个 beta，跟随等于持续引入未经上述检查的壳变化。
- **退回 Wails v2。** 从 v3 退回是重新移植而非改版本号，且 v2 没有托盘 API；换来的「stable」对单窗口自用阅读器收益有限。壳已压薄，退回成本基本只有一个文件，因此只作后备，仅在 v3 出现阻断缺陷时考虑。

## 后果

- Windows 上 Wails v3 通过纯 Go 调用 WebView2，不需要 CGO 或 mingw；构建文档不应再这样要求。
