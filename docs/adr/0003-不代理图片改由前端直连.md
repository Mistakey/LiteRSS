# 不在后端代理图片，改由 WebView2 直连原始地址

> Source: mrrss-275349 (D6)；spec 原文 `git show fe3c371b:docs/tracker/closed/2026-08/精简自用版/spec.md`

MrRSS 原本把文章 HTML 里的每个 `<img src>` 都替换成 `/api/media/proxy?url_b64=…`，由 Go 后端代拉、伪造 UA 与 Referer 绕防盗链、顺带落盘缓存（`internal/handlers/media` 1905 行 + `internal/cache` 590 行）。2026-08-27 决定删掉整套，前端改回直接引用原始图片地址。

关键事实是两侧的代理行为不一致：Wails 用的 WebView2 是 Chromium，读 Windows 系统代理；Go 的 `net/http` 不读，只认 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量。所以这套后端代理实际上把图片请求从「走代理的前端」挪到了「不走代理的后端」，是负优化。

实测支持删除：从库中 1500 篇正文提取 2163 张图、35 个域名，模拟 WebView2 条件（经系统代理、`Referer: http://localhost`）直连，前五大域名 `cdn.beekka.com`(1029 张)、`substackcdn.com`(153)、`p0.meituan.net`(123)、`img.36krcdn.com`(42) 全部 200；抽样 20 个域名中 16 个 200、3 个 301/302、1 个 403。成功率约 95%。

## 参照

Miniflux 的 `MEDIA_PROXY_MODE` 默认值是 `http-only`——只代理 HTTP 图片以规避混合内容拦截，HTTPS 图片一律直连。无差别代理全部图片本就不是主流做法。本项目更进一步取 `none`，因为桌面应用不存在「服务端渲染页面、浏览器拦截混合内容」的场景。

## 后果

- **`external-preview.redd.it` 的图片会裂（库中约 103 张，占 5%）。这是已知且可接受的状态，不要为它把图片代理加回来。** 该域名带不带 Referer 都返回 403，卡的是 URL 签名过期而非防盗链——原来那套图片代理对它同样无效，删除前后表现一致。
- 图片不再本地缓存，每次显示都重新下载（原缓存目录约 88 MB 随之消失）。
- 懒加载图片的处理留下了：原代理链路里顺带做的 `convertLazyImages`（把 `data-original` / `data-src` 搬到 `src`）与代理无关，是让站点的懒加载占位图在 WebView 里显示出真图的唯一手段，已抽到 `frontend/src/utils/lazyImages.ts`，现在对所有正文无条件执行。
- 图片请求自此走系统代理，与全文抓取（见 spec D13）行为一致。
- 若将来遇到成规模的防盗链失败，正确的做法是针对具体域名处理，而不是恢复无差别代理。
